## 💡 상세 해설 (자기 설명과 대조)

### 문제 1
정답: ② 기능적 > 순차적 > 교환적 > 절차적 > 시간적 > 논리적 > 우연적
- 제공 해설: 암기 구호 **"기·순·교·절·시·논·우"**. 응집도는 **강할수록 좋은 설계**다. 기능적(하나의 기능만 수행) → 순차적(앞 출력이 뒤 입력) → 교환적/통신적(같은 입출력 자료를 사용) → 절차적(순서대로 수행) → 시간적(특정 시점에 함께 실행) → 논리적(비슷한 성격끼리 묶음) → 우연적(관련 없는 것들이 모임).
- 오답 이유:
  - ① 교환적과 절차적의 순서가 뒤바뀌었다. 교환적이 절차적보다 강하다.
  - ③ 약한 것부터 강한 순으로 뒤집힌 나열이다.
  - ④ 교환적이 순차적보다 앞에 왔고, 논리적·시간적 순서도 뒤바뀌었다.

### 문제 2
정답: ② 스탬프 결합도(Stamp Coupling)
- 제공 해설: 결합도는 **약할수록 좋은 설계**이며 순서는 **"자·스·제·외·공·내"**(자료 < 스탬프 < 제어 < 외부 < 공통 < 내용). 스탬프 결합도는 배열·레코드·구조체 같은 **자료 구조 전체를 넘기지만 그중 일부만 사용**하는 경우다.
- 오답 이유:
  - ① 자료 결합도: 꼭 필요한 **단순 값(파라미터)만** 주고받는 가장 바람직한 결합도.
  - ③ 제어 결합도: 어떻게 동작할지 지시하는 **제어 플래그**를 넘기는 경우.
  - ④ 공통 결합도: **전역 변수**를 여러 모듈이 공유하는 경우.

### 문제 3
정답: ② 결합도는 낮게, 응집도는 높게
- 제공 해설: 모듈 독립성의 원칙. **응집도↑ 결합도↓**가 좋은 설계다. 모듈 안은 하나의 목적으로 똘똘 뭉치고(응집), 모듈끼리는 최대한 덜 얽혀야(결합) 수정·재사용·테스트가 쉬워진다.
- 오답 이유:
  - ① 정확히 반대 방향. 가장 나쁜 설계다.
  - ③ 결합도가 높으면 한 모듈 수정이 다른 모듈에 연쇄로 영향을 준다.
  - ④ 응집도가 낮으면 모듈 하나가 관련 없는 일을 여러 개 하게 된다.

### 문제 4
정답: ④ 유연성(Flexibility)
- 제공 해설: UI 설계 원칙 4가지 중 유연성은 **사용자의 다양한 요구를 수용하고 실수를 최소화·복구**할 수 있게 하는 것이다. 되돌리기(Undo), 다중 입력 방식 지원 등이 해당한다.
- 오답 이유:
  - ① 직관성: 누구나 **쉽게 이해하고 사용**할 수 있어야 한다.
  - ② 유효성: 사용자의 목적을 **정확하고 완벽하게 달성**할 수 있어야 한다.
  - ③ 학습성: 누구나 **쉽게 배우고 익힐** 수 있어야 한다.

### 문제 5
정답: ④ (가장 거리가 먼 것)
- 제공 해설: 오류 메시지는 **사용자를 비난하지 않아야** 한다. 원인을 사용자 탓으로 돌리는 표현은 UI 설계 지침에 정면으로 어긋난다. 메시지는 문제 상황과 **해결 방법**을 알려주는 것이 목적이다.
- 오답 이유 (옳은 지침들):
  - ① 이해하기 쉬운 언어로 작성 — 옳음. 기술 용어·에러 코드만 던지면 안 된다.
  - ② 회복 방법을 함께 제시 — 옳음. "무엇이 잘못됐다"에서 끝나면 안 된다.
  - ③ 소리·색 등 시청각 요소 병행 — 옳음. 텍스트 하나에만 의존하지 않는다.

### 문제 6
정답: ③ 루프 검사(Loop Testing)
- 제공 해설: **화이트박스 = 코드 내부 구조를 보고** 테스트. 기초 경로 검사, 조건 검사, 루프 검사, 데이터 흐름 검사, 각종 커버리지(문장·분기·조건)가 여기 속한다.
- 오답 이유 (모두 블랙박스):
  - ① 동치 분할 검사 — 입력을 유효/무효 범주로 나눠 대표값 검사.
  - ② 경곗값 분석 — 경계에 있는 값 검사.
  - ④ 원인-결과 그래프 검사 — 입력 조건과 출력의 인과를 그래프로 분석.
- 구분 요령: **코드를 봐야 하면 화이트박스**, 명세(입력→출력)만 보면 블랙박스.

### 문제 7
정답: ② 경곗값 분석(Boundary Value Analysis)
- 제공 해설: 오류는 범위의 **가장자리에서 잘 발생**한다는 경험에 기반한다. 입력 범위가 1~100이면 0, 1, 100, 101 같은 경계 값을 테스트 케이스로 잡는다.
- 오답 이유:
  - ① 동치 분할: 범위를 나눠 **각 범주의 대표값** 하나씩 검사. 경계가 아니라 대표값이 초점.

  - ④ 비교 검사: 여러 버전에 같은 입력을 넣어 결과를 비교.

### 문제 8
정답: ② 테스트 스텁(Test Stub)
- 제공 해설: **하향식(Top-Down) 통합 → 스텁**, **상향식(Bottom-Up) 통합 → 드라이버**. 하향식은 위에서부터 내려가므로 아직 없는 **아래쪽(하위 모듈)**을 스텁으로 대신한다.
- 오답 이유:
  - ① 테스트 드라이버: **상위 모듈** 역할을 대신해 하위 모듈을 호출하고 파라미터를 넘기는 가상 모듈. 상향식에서 필요.
  - ③ 테스트 스위트: 테스트 케이스의 집합.
  - ④ 테스트 오라클: 결과가 맞는지 판단하는 기준(참·샘플링·휴리스틱·일관성 검사 오라클).
- 암기: **하위를 대신하면 스텁, 상위를 대신하면 드라이버.**

### 문제 9
정답: ② 테스트 스위트(Test Suite)
- 제공 해설: 테스트 케이스들을 묶어 놓은 **집합**이 테스트 스위트다.
- 오답 이유:
  - ① 테스트 케이스: **입력값, 실행 조건, 기대 결과**를 명세한 하나의 항목.
  - ③ 테스트 시나리오: 테스트 케이스를 **실행 순서·절차**에 따라 묶은 것. 테스트 절차 명세서라고도 한다.
  - ④ 테스트 오라클: 결과의 정확성을 **판단하는 기준·메커니즘**.

### 문제 10
정답: ② 트리(Tree), 그래프(Graph)
- 제공 해설: **선형**은 자료가 일렬로 늘어선 구조(배열, 연결 리스트, 스택, 큐, 덱), **비선형**은 계층이나 망 형태(트리, 그래프)다.

### 문제 11
정답: ② 3
- 제공 해설: 트리의 차수 = **각 노드가 가진 자식 수 중 최댓값**. A는 자식 3개(B·C·D), B는 2개(E·F), D는 1개(G). 최댓값이 3이므로 트리의 차수는 3이다.

- 주의: **노드의 차수**(그 노드의 자식 수)와 **트리의 차수**(전체 노드 중 최댓값)를 구분할 것.

### 문제 12
정답: ① 제산법(Division Method)
- 제공 해설: 제산법은 키를 **소수로 나눈 나머지**를 홈 주소로 쓴다. 가장 단순하고 널리 쓰인다.
- 오답 이유:
  - ② 폴딩법: 키를 **여러 부분으로 나눠 더하거나 XOR**한 값을 사용.
  - ③ 기수 변환법: 키를 다른 **진법(기수)으로 변환**한 뒤 필요한 자릿수를 사용.
  - ④ 숫자 분석법: 키의 각 자릿수 분포를 조사해 **고르게 분포된 자리**를 골라 사용.
- 함께 알 것: 계수 분석법, 중간 제곱법, 무작위법. 그리고 서로 다른 키가 같은 주소를 갖는 현상을 **충돌**, 충돌한 키들을 **동의어(synonym)** 라고 한다.

### 문제 13
정답: ④ (옳지 않은 것)
- 제공 해설: **뷰는 ALTER 문으로 변경할 수 없다.** 구조를 바꾸려면 `DROP VIEW` 후 다시 `CREATE VIEW` 해야 한다. 뷰에 사용할 수 있는 것은 CREATE와 DROP뿐이다.
- 오답 이유 (옳은 설명들):
  - ① 물리적으로 존재하지 않는 가상 테이블 — 옳음. **정의만 저장**된다.
  - ② 정의가 시스템 카탈로그에 저장 — 옳음.
  - ③ 기본 테이블이 삭제되면 뷰도 자동 삭제 — 옳음. 뷰는 기본 테이블에 종속된다.
- 함께 알 것: 뷰 삭제 시 `CASCADE`(연쇄 삭제)와 `RESTRICT`(참조 중이면 취소) 옵션.

### 문제 14
정답: ③ (옳지 않은 것)

  - ② 데이터 딕셔너리라고도 부름 — 옳음.
  - ④ SELECT로 조회 가능 — 옳음. **읽기는 되고 쓰기는 안 된다**가 핵심.

### 문제 15
정답: ② 타원
- 제공 해설: E-R 다이어그램 기호는 **사각형=개체(Entity)**, **타원=속성(Attribute)**, **마름모=관계(Relationship)**, **선=연결**이다.
- 오답 이유:
  - ① 사각형: 개체 타입.
  - ③ 마름모: 관계 타입.
  - ④ 이중 사각형: 약한 개체(Weak Entity).

### 문제 16
정답: ② 대체키(Alternate Key)
- 제공 해설: 유일성과 최소성을 모두 만족하는 것이 **후보키**이고, 그중 대표로 선정한 것이 **기본키**, 선정되지 못한 나머지가 **대체키**다.
- 오답 이유:
  - ① 슈퍼키: 유일성은 만족하지만 **최소성은 만족하지 않는** 키.
  - ③ 외래키: 다른 릴레이션의 기본키를 참조하는 속성.
  - ④ 복합키: 두 개 이상의 속성으로 이루어진 키(별개의 분류 기준).
- 정리: 슈퍼키 ⊃ 후보키 = 기본키 + 대체키.

### 문제 17
정답: ④ 지속성(Durability)
- 제공 해설: 지속성(영속성)은 **커밋된 결과는 장애가 나도 살아남는다**는 성질이다. 로그와 회복 기법으로 보장한다.
- 오답 이유:
  - ① 원자성: 전부 반영되거나 전혀 반영되지 않거나(All or Nothing). **중간 상태로 남지 않음.**
  - ② 일관성: 트랜잭션 수행 전후로 데이터베이스가 **일관된 상태**를 유지.
  - ③ 격리성(고립성): 실행 중인 트랜잭션의 **중간 결과를 다른 트랜잭션이 볼 수 없음.**
- 암기: **원·일·격·지**. "장애가 나도 남는다"는 지속성 하나뿐이다.

### 문제 18
정답: ① 기밀성(Confidentiality)
- 제공 해설: 정보보안 3요소(CIA)는 **기밀성·무결성·가용성**. 그중 기밀성은 **인가된 사람만 볼 수 있게** 하는 것이다.
- 오답 이유:
  - ② 무결성: 인가되지 않은 방법으로 **변경되지 않도록** 보장.
  - ③ 가용성: 인가된 사용자가 **필요할 때 접근**할 수 있도록 보장.
  - ④ 책임추적성: 3요소에 포함되지 않는 부가 요소(누가 무엇을 했는지 추적).
- 주의: 3요소를 묻는 문제에서 **부인방지·인증·책임추적성**은 답이 아니다.

### 문제 19
정답: ② 위험 식별 → 위험 분석 및 평가 → 위험 관리 계획 → 위험 감시 및 조치
- 제공 해설: **찾고(식별) → 따져보고(분석·평가) → 계획 세우고 → 지켜보며 조치**하는 자연스러운 흐름이다. 무엇이 위험인지 모르는 상태에서 분석이나 계획이 먼저 올 수 없다.
- 오답 이유:
  - ① 식별보다 분석이 앞섰다. 대상이 없는데 분석할 수 없다.
  - ③ 계획이 식별보다 앞섰다.
  - ④ 계획이 분석·평가보다 앞섰다. 평가 없이 대응 계획을 세울 수 없다.

### 문제 20
정답: ② CBC(Cipher Block Chaining)
- 제공 해설: CBC는 **이전 암호문 블록과 현재 평문 블록을 XOR한 뒤 암호화**한다. 블록이 사슬(chaining)처럼 엮여서, 같은 평문 블록이라도 매번 다른 암호문이 나온다. 첫 블록에는 **초기화 벡터(IV)** 를 쓴다.
- 오답 이유:
  - ① ECB: 각 블록을 **독립적으로** 암호화. 같은 평문 → 같은 암호문이라 패턴이 드러나 가장 취약하다.
  - ③ CFB: 이전 **암호문을 암호화한 결과**와 현재 평문을 XOR. 스트림 암호처럼 동작한다.
  - ④ OFB: 이전 **암호 알고리즘의 출력**을 다시 입력으로 사용. 평문과 무관한 키 스트림을 만든다.
- 함께 알 것: CTR 모드(카운터 값을 암호화해 사용). 운영 모드 5종은 **ECB·CBC·CFB·OFB·CTR**.
